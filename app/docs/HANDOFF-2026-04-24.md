## Research that informed the build

Orlando asked for 7 parallel agents to do 7 minutes of deep research each, then synthesize. All 7 returned substantive findings. Summaries:

**1. Capacitor hybrid architecture.** Use Capacitor 7 (early-2025 stable). For wake/sleep screens, the right pattern is local-bundled HTML + native plugins, not React Native via `native-navigation` (mixing runtimes is fragile). Live updates: load the live URL for content, use Capgo for OTA on the local bundle only. WebView tuning: `androidScheme: 'https'`, safe-area insets via `env(safe-area-inset-*)`, `viewport-fit=cover`. Plugin ecosystem: official `@capacitor/*` packages are reliable; community plugins need a peer-dep check before installing.

**2. Android alarm implementation.** `AlarmManager.setAlarmClock()` is the only API that survives Doze and App Standby — never use `setExactAndAllowWhileIdle()` for a wake alarm. Permissions: `USE_EXACT_ALARM` (auto-granted to alarm apps Android 14+), `USE_FULL_SCREEN_INTENT`, `FOREGROUND_SERVICE_MEDIA_PLAYBACK`, `RECEIVE_BOOT_COMPLETED`. Foreground service must start within 5s of receiver fire. AlarmActivity uses `setShowWhenLocked(true)` + `setTurnScreenOn(true)`. **Custom plugin is unavoidable** — no off-the-shelf Capacitor plugin handles this end-to-end. OEM detection (Xiaomi, Samsung, Oppo, OnePlus, Huawei) needed because of aggressive battery managers; use `dontkillmyapp.com` patterns with deep-link onboarding.

**3. iOS alarm workarounds.** Apple has no public alarm API. The shipping pattern (used by Alarmy, Sleep Cycle, Rise, Pillow): `UNNotificationInterruptionLevel.timeSensitive` local notification with bundled <30s `.caf` sound + silent-audio keep-alive via `AVAudioSession(.playback)` gated to armed-alarm state only. Backup notification 60s later. Critical Alerts entitlement is reserved for medical/safety apps — a wellness app will be denied; don't pursue. Honest reliability ceiling: ~95-98% with plugged-in, app-open users.

**4. Background audio/video stack.** Audio: `@mediagrid/capacitor-native-audio` (already includes lock-screen MPNowPlayingInfoCenter on iOS + MediaSessionCompat on Android — meaning we don't need a separate media-session plugin). Video: `@capgo/capacitor-video-player` (native AVPlayer/ExoPlayer, supports HLS/DASH, PiP). Avoid Howler.js in WebView (iOS suspends Web Audio context on lock). Audio focus is handled internally by the native plugins. For wake-up fade-in, poll `setVolume(n)` on a 50-100ms tick over the fade duration. Sleep timer should be scheduled via `@capacitor/background-runner`, not `setTimeout` (which dies on iOS suspension).

**5. Offline-first content sync.** Skip service workers in Capacitor — they misbehave in WKWebView under App-Bound Domains restrictions. Use native: `@capacitor/preferences` for keys/manifest hashes, `@capacitor/filesystem` for JSON files (~500KB), `@capacitor-community/sqlite` with FTS5 for fast search over 600+ resources. Sync architecture: tiny `/content-version.json` manifest polled on cold start + resume, conditional GETs with `If-None-Match` ETags. Media: Cloudflare R2 for audio (cheaper, presigned URLs), Cloudflare Stream for video (HLS/ABR, signed URLs). Default user download quota: 2 GB with LRU eviction.

**6. Wake/sleep UX patterns from leading apps.** Studied Alarmy, Sleep Cycle, Calm, Headspace, Oura, Rise, Insight Timer, Loona. Borrow: the principle that dismissing requires a deliberate action, smart-wake-window concept, fade-out arc (Calm's softening narration), un-engaging-by-design content for sleep (Headspace), read-only HealthKit/Health Connect integration without displaying scores. Reject (incompatible with FRQNCY values): leaderboards, sleep scores, streaks, gamified missions, celebrity-voice-as-product, sleep-debt as a quantified liability, performance/optimization framing.

**7. App Store + Play Store submission.** Top 5 rejection risks: Apple Guideline 4.2 (thin wrapper), iOS background audio not audible during review, Play foreground-service video too vague, `USE_EXACT_ALARM` declined, privacy label/Data Safety mismatch. Mitigations baked into spec. Native alarm feature is what saves us from 4.2. Need a 60-second unlisted YouTube demo for Play foreground service declaration. Stay positioned as wellness/mindfulness/alarm — never therapeutic, clinical, or medical claims.

## Architecture decisions (locked)

- **Framework:** Capacitor 7
- **Bundler:** Vite 5 + TypeScript
- **Routing:** Hybrid — WebView iframe loads frqncy.network for content; local HTML bundle (`/app/wake.html`, `/app/sleep.html`, etc.) serves native-feeling screens
- **Audio:** `@mediagrid/capacitor-native-audio` (drops `@jofr/capacitor-media-session` because mediagrid already has lock-screen wiring)
- **Video:** `@capgo/capacitor-video-player`
- **Storage:** Preferences (keys), Filesystem (JSON), SQLite FTS5 (search index), Capgo Downloader (media)
- **Alarms:** Custom `FrqncyAlarm` plugin (Kotlin + Swift skeletons written)
- **Backend:** Cloudflare R2 (audio) + Cloudflare Stream (video) + Cloudflare Pages (existing site)
- **Live updates:** Capgo for local bundle; content updates flow through `/content-version.json` manifest

## Values that constrain UX (non-negotiable)

These came from Orlando's earlier memory and were re-affirmed throughout the conversation. Any future agent making UX decisions must respect them:

- Cooperation over competition. No leaderboards, no streaks, no "X days in a row."
- Inner experience over metrics. No sleep scores, no readiness numbers.
- Conviction as self-expression, not ranking.
- The gesture is the arrival — dismissing an alarm is one breath (~6 sec hold), not a math puzzle.
- Un-engaging by design for sleep — narration that doesn't reward attention.
- "Return" instead of snooze.
- Phone face-down pauses visual; audio continues.
- HealthKit/Health Connect read-only, used only to time the wake window, never displayed back.

## Build commands reference

From `/FRQNCY WEBSITE/app/`:

```bash
npm install                       # install deps
npm run dev                       # vite dev server, browser-testable
npm run build                     # build local bundle + regen content-version.json
npm run tag:moments               # re-tag resources.json with moment field
npm run cap:sync                  # build + sync into native projects
npm run cap:android               # open Android Studio
npm run cap:ios                   # open Xcode
npm run android:run               # build + sync + run on Android device/emulator
npm run ios:run                   # build + sync + run on iOS device/simulator
```

The website-side manifest regeneration must run as part of the website's deploy. Add to the Cloudflare Pages build command:

```bash
node app/scripts/build-manifest.mjs
```

(That's how content updates flow to the app — without this step, the app won't know the website changed.)
