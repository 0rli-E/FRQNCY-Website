**Web bundle:**

**JS layer:**
- `src/app/bedside.html`: arm button calls `FrqncyAlarm.schedule()` with real

## To produce the APK (Orlando, in your terminal)

```bash
cd ~/Documents/Claude/Projects/FRQNCY\ WEBSITE/app
rm -rf node_modules package-lock.json
npm install
```

(Cowork sandbox can't finish the post-install renames, so this runs in your
terminal. Should complete in 60–120 seconds.)

```bash
npm run cap:sync
```

(This runs `vite build` + `cap sync android` which copies the web bundle into
`android/app/src/main/assets/public/` and regenerates `capacitor.build.gradle`.
Already done in the sandbox, but `cap sync` ensures the project matches your
exact node_modules state.)

Install Android Studio if you haven't:

1. Download from <https://developer.android.com/studio>
2. Open the project: `~/Documents/Claude/Projects/FRQNCY WEBSITE/app/android`
3. First Gradle Sync downloads SDK 35 + Kotlin compiler — ~5 minutes the first
   time, instant after.
4. If sync errors: paste the message to Claude. Most likely:
   - **Kotlin version mismatch** → bump `kotlinVersion` in `variables.gradle`.
   - **`R.layout.activity_alarm` not found** → File → Invalidate Caches → Restart.
   - **`@CapacitorPlugin` not found** → confirm `npm install` completed
     successfully and `node_modules/@capacitor/android/` exists.

Build the APK:

- **Debug build (fastest, signed with debug keystore):**
  `Build → Build Bundle(s) / APK(s) → Build APK(s)`. Output appears at
  `android/app/build/outputs/apk/debug/app-debug.apk`. AirDrop / email / GDrive
  to your phone, install (you'll need to allow "Install unknown apps" for the
  app you used to transfer it).

- **Run on connected device:** Plug in your Android phone. Enable
  Developer Options → USB Debugging. Click the green ▶ in Studio. App installs
  and launches. (Studio remembers the device — subsequent builds are 5–10s.)

- **Signed release APK (for Play Internal Testing or wider sideload):**
  `Build → Generate Signed Bundle / APK → APK → release`. Generate a keystore
  the first time:
  ```bash
  keytool -genkey -v -keystore frqncy-release.keystore -alias frqncy -keyalg RSA -keysize 2048 -validity 10000
  ```
  **Save the keystore + password somewhere persistent** — you need them for
  every future release.

## What to verify on the phone

1. Open the app — bedside / explore / you tabs visible.
2. Bedside tab → set a time 1 minute out → tap "arm for tonight".
3. First time you arm, the permission flow runs:
   - Notifications dialog (Android 13+) → allow
   - "Alarms & reminders" deep-link if exact alarm denied (Android 12+) → grant
4. Lock the phone. Wait.
5. Alarm fires:
   - Lock-screen full-screen UI appears (the breath-hold ring)
   - Audio: gentle 432Hz tone (or system default if MediaPlayer fell back)
   - Volume fades in over 90s (ease-in quadratic curve)
6. Hold the ring for 6 seconds → app routes to wake.html.
7. Tap snooze instead → alarm re-arms for 9 minutes from now.
8. Restart the phone. The alarm survives — BootReceiver re-arms from
   SharedPreferences before user unlock (direct-boot aware).

Things that won't work yet (expected):
- Sleep tab "let me drift" plays nothing useful unless you install
  `@mediagrid/capacitor-native-audio` (Phase 3) and tag at least one
  evening-moment resource with a direct audio URL in `resources.json`.
- Wake tab "move with me" opens an external browser if no NativeAudio plugin.
- iOS hasn't been built yet — Xcode side requires the .swift to be added to
  the .pbxproj manually (Files → Add Files to "App"…).

## Reliability expectations on Android (per Stream 2 research)

- **Pixel / Android One:** ~99% if permissions correct.
- **Samsung One UI 7:** ~95% with battery optimization off + "Never sleeping
  apps" set; ~70% without OEM onboarding.
- **Xiaomi HyperOS:** 80–90% with full onboarding (Autostart on, Battery
  No restrictions, lock in Recents); 40–60% without.
- **Oppo / Realme / OnePlus:** 75–85% with onboarding.
- **Vivo / iQOO:** 70–80% even with perfect onboarding — most aggressive.

The OEM guidance modal in `bedside.html` triggers on first arm if
`getOemGuidance().isAggressive === true` and provides exact step-by-step
instructions per manufacturer. User is expected to follow them once.
