## 1. Executive summary

The Apr-24 architecture was right and is still right in 2026 — hybrid Capacitor, local bundle for native screens, live website inside an iframe, custom alarm plugin on both platforms. Two years of platform drift since that research changed *seven specific implementation details* but not the shape. This roadmap absorbs those changes and sequences the work to ship a Play Store + App Store v1 in 12 weeks on the existing solo / ~$100 budget.

The seven decisions worth carrying out of this:

**(a) Stay on Capacitor 7 through July 2026.** Capacitor 8 (8.0.2 shipped 27 Jan 2026) is real and small to migrate, but `@capacitor-community/sqlite` has no Cap 8 release yet. The bigger architectural risk is using `server.url` to load `frqncy.network` in production — Apple has flagged this for hybrid apps. Use the iframe-in-local-shell pattern that's already wired in `src/main.ts`; keep `server.url` unset.

**(b) Skip SQLite entirely for v1.** With 766 resources and 146 topics, an in-memory FlexSearch index built at launch is faster (sub-ms queries, ~50ms build) than a native SQLite FTS5 plugin and removes the only native build that doesn't exist yet. Revisit when UGC arrives.

**(c) Lock in mediagrid v3.0.0 for audio.** It shipped 23 Jan 2026 with built-in fade APIs (`setVolume(value, duration)` maps to AVAudioPlayer's native fade on iOS and ExoPlayer ramping on Android). Use the native fade — do *not* poll `setVolume` on a 50-100ms tick like the SPEC originally suggested. Background-throttled timers are unreliable on iOS and battery-hostile on Android.

**(d) Drop the iOS reliability claim from 95-98% to 92-96%.** iOS 17.4 tightened audio-session enforcement and iOS 18's Sleep Focus is more aggressive at suppressing notifications. The keep-alive session must use `.mixWithOthers` or it dies on any incoming audio. Be honest in onboarding — frame FRQNCY as "a wake companion, not a replacement for the iOS Clock for safety-critical wakes."

**(e) Add a MediaSession to AlarmService on Android.** Android 16 (API 36, expected mid-2026) is rumored to require an active MediaSession to keep `mediaPlayback` foreground service type valid. Wire it now; the cost is one class.

**(f) Honesty-as-marketing on Android OEM reliability.** Pixel 99%, Samsung 95% with battery optimization off, Xiaomi/Oppo/OnePlus 80-90% with full onboarding, Vivo 70-80% even perfectly configured. No competitor ships this disclosure. FRQNCY should — a pre-arm one-liner: *"Phone alarms on Android can fail. Here are the three settings to fix that, and a pairing recommendation if you can't risk a missed wake."*

**(g) Ship v1 free with no IAP, no ATT, "Data Not Collected" privacy labels.** Apple Health & Fitness category, age 4+/Everyone. Out-of-app "Support FRQNCY" Stripe link in settings to dodge the 30% cut. Pricing decisions wait until day 90.

## 2. State today (snapshot)

The Capacitor 7 scaffold lives at `FRQNCY WEBSITE/app/`. `npx cap add android` and `npx cap add ios` have run, native projects exist. Hybrid router in `src/main.ts` correctly handles the iframe split, deep links (`frqncy://wake?...`), hardware back button, and offline banner. SyncManager does proper stale-while-revalidate against `/content-version.json` with ETag conditional GETs. `tag-moments.mjs` has run — 109/766 resources are tagged with `morning`/`evening`/`stillness`/`release`. Local screens (wake, sleep, alarm, bedside, settings) are styled, breath-hold gesture works, three-target sleep chooser works.

The custom `FrqncyAlarm` Kotlin plugin skeleton exists at `app/android-plugin/` with `setAlarmClock()` correctly wired and OEM guidance for six manufacturers. **It has not been copied into `app/android/app/src/main/`.** The four supporting Kotlin classes (`AlarmReceiver`, `AlarmService`, `AlarmActivity`, `BootReceiver`) and the Room-backed `AlarmStore` don't exist yet. The live `AndroidManifest.xml` declares only `INTERNET`. `MainActivity.java` is the default `extends BridgeActivity` stub. iOS has the parallel skeleton in `app/ios-plugin/` and the same gap.

Audio plugin not yet installed. Video plugin not yet installed. No bundled default audio. No Privy / no auth. No store accounts created. CI/CD not set up. OTA not wired. Privacy manifests not written.

What's blocked on the user's machine: Android Studio install, `xcode-select` switch, CocoaPods install. Cowork sandbox can't write `.git/HEAD.lock` or finish multi-package npm installs that do post-install renames; those steps must run in a regular terminal.

| Alarm-app declaration | `USE_EXACT_ALARM` declared on Play with "alarm clock or calendar app" use-case. Subtitle/short description must contain the word "alarm." | Reviewers reject when alarm feels secondary. |

## 4. Twelve-week plan (2026-04-29 → 2026-07-28)

### Phase 0: Foundation (Week 1, Apr 29 – May 5)

Source-side wiring that doesn't need Android Studio or Xcode. **Goal: native projects open cleanly with the alarm plugin recognized.**

- Convert `MainActivity.java` to Kotlin and register the FrqncyAlarm plugin
- Copy `FrqncyAlarmPlugin.kt` into `android/app/src/main/java/network/frqncy/alarm/`
- Merge `AndroidManifest.additions.xml` into the live manifest (eight permissions, two receivers, the foreground service, the alarm activity)
- Add the `Theme.Frqncy.Alarm` style + `activity_alarm.xml` layout
- Mirror the iOS plugin wiring: copy `FrqncyAlarmPlugin.swift` into `ios/App/App/FrqncyAlarm/`, merge Info.plist additions (UIBackgroundModes audio, NSAppTransportSecurity), register in `AppDelegate.swift`
- Replace the `server.url`-style assumption with the iframe pattern in `main.ts` (already mostly there — verify and lock)
- Install Android Studio (manual, by Orlando), `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`, `brew install cocoapods`

**Exit criteria:** `npm run cap:android` opens Studio with no errors; `npm run cap:ios` opens Xcode with `pod install` clean. Plugin is registered but doesn't fire yet.

### Phase 1: Android alarm end-to-end (Weeks 2–3, May 6 – May 19)

Write the four supporting Kotlin classes + Room store. **Goal: alarm rings on a Pixel emulator from arm to dismiss.**

- `AlarmReceiver.kt` — `directBootAware="true"`, exported false, acquires 10s wake lock, calls `startForegroundService` with payload, re-schedules next occurrence before returning
- `AlarmService.kt` — typed `mediaPlayback`, `startForeground` within 5s, builds `setFullScreenIntent` notification with `CATEGORY_ALARM`, plays alarm tone via ExoPlayer with audio attributes `USAGE_ALARM`, registers a `MediaSessionCompat` and sets it active (Android 16 readiness)
- `AlarmActivity.kt` — sets `setShowWhenLocked(true)` + `setTurnScreenOn(true)` programmatically (don't trust manifest alone), disables back gesture via `OnBackPressedCallback`, loads `app/alarm.html` from the bundle through Capacitor's bridge, sends Stop/Snooze intents to the service
- `BootReceiver.kt` — listens for `BOOT_COMPLETED` + `LOCKED_BOOT_COMPLETED`, rehydrates from Room before user unlock
- `AlarmStore` → Room: `@Database(directBootAware = true)`, encrypted-storage flag on Android N+, table for recurring rules + snooze history + sound URI + label
- Hook a `Crashlytics`-equivalent (or simple log telemetry to Cloudflare Workers) around `ForegroundServiceStartNotAllowedException` — most common silent failure on Android 14+
- Wire `bedside.html` arm button to `FrqncyAlarm.schedule()`; surface OEM guidance on first arm via `FrqncyAlarm.getOemGuidance()`

**Exit criteria:** Pixel emulator running Android 15. Set alarm 1 minute out, lock device, alarm fires, full-screen UI shows, breath-hold dismisses, app returns to bedside. Reboot the emulator with an armed alarm — it fires after reboot.

### Phase 2: iOS bedside end-to-end (Weeks 3–4, May 13 – May 26, parallel)

Write the iOS-side equivalents. **Goal: bedside mode works on a plugged-in iPhone simulator from arm to dismiss.**

- `FrqncyAlarmPlugin.swift` — request `UNUserNotificationCenter` permission with `.timeSensitive` option
- Schedule primary `UNNotificationRequest` with `interruptionLevel = .timeSensitive` carrying bundled `morning.caf` (≤30s)
- Schedule backup notification at +60s with same payload
- `SilentKeepAlive.swift` — `AVAudioSession.setCategory(.playback, mode: .default, options: [.mixWithOthers])`, looping near-silent pink noise (-60 dB, not zero-amplitude — Apple flags pure-silent buffers), gated to armed-alarm state via `armKeepAlive()` / `disarmKeepAlive()`
- ActivityKit Live Activity for the "armed" pill — Dynamic Island on iPhone 14 Pro+, Lock Screen elsewhere
- Listen for `AVAudioSession.routeChangeNotification` to detect headphone/Bluetooth disconnect and re-prime the session
- iOS 18 Sleep Focus onboarding — first arm shows a Sheet explaining "add FRQNCY to Sleep Focus + enable Time Sensitive override" with deep-link to Settings
- Wire `bedside.html` arm button to call `FrqncyAlarm.armKeepAlive()` on arm and `disarmKeepAlive()` on disarm

**Exit criteria:** iPhone simulator (iOS 18). Arm alarm 1 min out, background app, alarm notification fires with bundled sound, tapping it opens wake.html, breath-hold dismisses. Live Activity visible on Lock Screen between arm and fire.

### Phase 3: Audio + sleep flow (Weeks 4–5, May 27 – Jun 9)

Wire actual audio playback. **Goal: sleep flow plays a moment-tagged resource end-to-end with the volume curve.**

- `npm install @mediagrid/capacitor-native-audio @capacitor-community/native-audio @capgo/capacitor-video-player` (in terminal — Cowork can't finish npm renames)
- Wire `sleep.html` to mediagrid for long-form playback, fade volume via `setVolume({ volume: 1.0, duration: 60 })` for fade-in, `stop({ fadeOut: true, fadeOutDuration: 600 })` for sleep timer
- Implement the spec's volume curve via *file-encoded* envelope, not JS polling — pre-render the 100→40→silence ramp into the audio file itself and use mediagrid's stop-with-fadeout for the tail
- Wire `wake.html`'s "move with me (3 min)" button to a morning-tagged resource via `resources.json`
- Bundle a default `morning.mp3` and `evening.mp3` so first-launch users without internet get something
- Bundle `silent.wav` (or rather the -60dB pink noise) for iOS keep-alive
- Add procedural "let me drift" mode v1: drone + sparse bell tones + optional rain, mixed in JS via Web Audio API with frequency roll-off across 30 minutes (high-frequency content drops to leave only sub-200Hz drone). Single layered audio file is acceptable for v1 — full procedural engine is v2.

**Exit criteria:** Both platforms. Tap "let me drift" on bedside → soundscape plays for 45 min with correct volume curve and frequency roll-off → ends silently → screen blanks. Lock-screen controls visible during playback.

### Phase 4: Sync + offline + content tagging (Week 6, Jun 10 – Jun 16)

Polish the content layer. **Goal: cold-start works offline on day zero, tag coverage at 25%.**

- Add an install-time hydration step: ship `bundle.json` (search + resources + content merged) inside the app's assets dir so first launch works offline before any sync
- Update `build-manifest.mjs` to emit the bundle and per-topic shards
- Wire FlexSearch index built at startup against the cached bundle
- Re-run `tag-moments.mjs` after improving regex coverage — target 200/766 tagged (currently 109/766)
- Wire `settings.html` storage + sync rows to real Preferences values (last-synced timestamp, downloaded MB)
- Add the `_redirects` rule on Cloudflare Pages so `/content-version.json` is served with `Cache-Control: public, max-age=60` (low TTL so changes propagate fast)

**Exit criteria:** Airplane-mode the device, install fresh, app opens, content visible, search works.

### Phase 5: OEM onboarding + accessibility + UX (Week 7, Jun 17 – Jun 23)

Address what Stream 6 surfaced. **Goal: first-arm flow on Android shows the right OEM guidance; the breath-hold has accessible alternatives.**

- First-arm Android: detect `Build.MANUFACTURER`, show the corresponding `getOemGuidance()` copy with deep-link to settings page if available, plus a generic "phone alarms on Android can fail" honesty disclaimer
- First-arm iOS: Sleep Focus onboarding sheet (see Phase 2)
- Accessibility settings panel: three dismiss modes — breath hold (default), long-press hold, triple-tap. All resolve to the same dismiss event.
- VoiceOver / TalkBack labels on the dismiss ring, progress announces at 25% increments
- Switch Access compatibility (Android), `accessibilityLabel` on every interactive element
- Reduced-motion support: ring fills linearly when `prefers-reduced-motion`
- Hearing-impaired wake mode: 60-second slow rising haptic pattern, no audio
- Cap snoozes at 2; the third "snooze" replaces with a breath-hold. Default snooze duration: 9 minutes (Loftie pattern).
- Add the two-phase pre-wake (soft tone 20 min before set time, room-fill at set time) as opt-in toggle, default ON

**Exit criteria:** All accessibility paths work in QA. OEM guidance fires correctly on a Samsung emulator (or real device).

### Phase 6: Privacy + manifests + reviewer notes (Week 8, Jun 24 – Jun 30)

Compliance plumbing. **Goal: binaries pass privacy/data-safety auto-checks on first upload.**

- Hand-write `ios/App/App/PrivacyInfo.xcprivacy` declaring the four required-reason APIs (UserDefaults CA92.1, FileTimestamp C617.1, SystemBootTime 35F9.1, DiskSpace E174.1) + `NSPrivacyTracking=false` + empty `NSPrivacyCollectedDataTypes`
- Audit any third-party SDK for its own `PrivacyInfo.xcprivacy` (mediagrid, capgo-video-player); pull manifests if missing
- Play Data Safety form: Data collected = None, Shared = None, Encrypted in transit = Yes, Deletion path = link to `frqncy.network/delete` (build that page)
- Apple Privacy Nutrition Label: Data Not Collected, all categories
- Reviewer notes — Apple template (~150 words): list native features beyond webview as bullets (alarm, biometric lock, deep links, offline shell, Live Activity, Health read-only)
- Reviewer notes — Play template (~150 words): name `mediaPlayback` FGS type, point to unlisted FGS demo video, justify USE_EXACT_ALARM in 3 sentences

**Exit criteria:** Both binaries upload to TestFlight + Play Internal Testing without auto-rejection.

### Phase 7: Beta + iteration (Weeks 9–10, Jul 1 – Jul 14)

Real-device testing. **Goal: 20 beta users across both platforms, no critical bugs after 5 days of dogfood.**

- Set up TestFlight internal group (instant) + Play Internal Testing track (up to 100 testers)
- Record 30–60s screen recordings for Play FGS declaration video (no music, no overlay text, plain narration)
- Push v0.2 to internal beta
- Crashlytics or equivalent for both platforms — wire from day one
- Beta test plan: 5 testers on Pixel, 5 on Samsung, 5 on Xiaomi/Oppo/OnePlus, 5 on iPhone (mix iOS 17 / 18). Daily-arm-and-wake protocol for one week. Specific reliability ask: "did the alarm fire? what was different about the misses?"
- Wire Capgo OTA so v0.3 fixes ship without store re-submit
- Iterate on any P0 reliability bugs

**Exit criteria:** Crash-free rate ≥ 99% on both platforms over 5 days. Alarm fire rate ≥ 95% on Pixel, ≥ 80% on Xiaomi (matching the honesty-as-marketing claim).

### Phase 8: Submission (Week 11, Jul 15 – Jul 21)

Submit to both stores. **Goal: v1.0 in review.**

- App Store Connect: upload, fill metadata, attach reviewer notes, screenshots (5–8 per device class), submit
- Play Console: upload, fill Data Safety, USE_EXACT_ALARM declaration, FGS video link, screenshots, submit to Closed Testing → promote to Production
- Buffer 2 weeks for rejection-resubmit cycle
- Have rapid-response prepared for the two highest risks: Apple 4.2 (push back with the "native features" list) and Play FGS video (re-record with clearer steps if rejected)

**Exit criteria:** Both submissions accepted or in known revision.

### Phase 9: Launch + observability (Week 12, Jul 22 – Jul 28)

Public release. **Goal: v1.0 live, telemetry working, revenue placeholder live.**

- Public release on both stores
- Settings → "Support FRQNCY" link to Stripe checkout on `frqncy.network/support` (out-of-app, no IAP cut)
- Set up basic dashboards: install count, crash-free rate, alarm fire rate (anonymous), session minutes
- Push announcement on existing channels (frqncy.network, social tab)
- Schedule day-90 review: pricing model (free / pay-what-feels-right / founder badge), social tab integration, audio content commissioning
