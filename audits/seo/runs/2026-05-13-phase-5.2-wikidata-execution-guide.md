## Background research (WebSearch, 2026-05-13)

Five WebSearch queries verifying the current 2026 Wikidata workflow. Key findings:

1. **Special:NewItem URL still works as-is** — Wikidata's flow has not changed. Label + description + click Create → redirect to Q-number page → add statements one at a time.
2. **No "Articles for Creation" equivalent on Wikidata.** Direct mainspace creation is standard. New accounts can create items immediately (unlike Wikipedia, which requires autoconfirmed status).
3. **Statement-by-statement reference citation** — confirmed the modern flow: publish the statement first, then click "add reference" inside the saved statement box, type `reference URL` (P854), paste the URL, optionally add `retrieved` (P813) and `title` (P1476), publish the reference.
4. **Deletion reasons (most common in 2026):** vandalism, spam/promotional, out of scope, notability fail, empty item, duplicate. Notability bar for organizations is "any subject discussed in a single secondary source" — FRQNCY clears this comfortably; Intaaya is the most vulnerable.
5. **Self-published references are allowed** for basic facts (founder, founding date, official website). Pairing with a third-party reference strengthens claims but is not required for non-contested statements.

## Editorial decisions

These choices were made in the execution guide that weren't fully specified in the brief:

1. **Creation order:** FRQNCY → Orlando → Podcast → Intaaya. The order is dictated by dependency edges (Orlando references FRQNCY; Podcast references both; Intaaya references FRQNCY). Documented in §0.9 of the guide.
2. **`founded by` deferral:** the FRQNCY entity is created with `founded by` empty initially, then back-filled after the Orlando entity exists. This avoids the "linking to a non-existent Q-number" pitfall the brief flagged.
3. **Intaaya `part of` row deferred:** the brief suggested `part of FRQNCY Sanctuary network`. There's no dedicated Wikidata entity for the Sanctuary sub-program. Guide recommends skipping the row rather than soft-linking to Q-FRQNCY, to keep Intaaya's statements clean.
4. **X username gated on handle claim status:** the brief listed `X username = frqncy_network`. Per `SAMEAS-MATRIX.md`, that handle is `not-yet-created`. Guide instructs Orlando to skip the X username row entirely if the handle is still vacant at execution time — claiming sameAs to a vacancy is the same soft-inaccuracy that triggered the SAMEAS audit.
5. **`archives at` (P485) substituted with `archived at URL` (P1065):** P485 is technically for the institutional archive, not the GitHub repo. The guide uses P1065 with the GitHub URL.
6. **Description style:** all four descriptions rewritten to lowercase dictionary-gloss style (Wikidata convention) — the brief's descriptions read like marketing prose. Character counts confirmed under the 250 limit.
