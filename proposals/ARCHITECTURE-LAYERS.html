Three layers, one network.

How FRQNCY stays editable, individual, and beautiful at the same time — and why the cost per new page falls as the network grows. With an audit of what's already built.

The three layers.

Every page is the result of three things stacked on top of each other. Each layer answers a different question, has a different edit pattern, and grows at a different rate.

EDIT FREQUENCY · LAYER · FILE COUNT

How one page gets built.

The generator dereferences the topic YAML against the bed files, applies the chrome, and emits HTML. The page is individual because the topic YAML is individual. The data is canonical because the bed files are canonical.

DEREFERENCE · COMPOSE · RENDER

One edit, many pages.

The data-availability win. Update Lightning's logo in one bed file → every page that surfaces Lightning updates on regen. The Bitcoin sub-hub today, the future Lightning topic page, the Payments topic — same edit, three pages improved.

Read: the substrate is mostly there. The bed files exist. The chrome exists. The reference generator exists (the crypto sub-hub one). The MCP server exposes the world model to the harness. What's missing is one generalised topic-page generator that reads YAML, plus the YAML schema, plus a commission-topic skill in the harness. Three concrete artefacts, not a rewrite.

The next concrete move.

Three artefacts, in order. None require a rewrite. All are additive.

1data/topics/_schema.yaml30 minThe contract every later piece composes against. Defines hero, prelude, counter-box, seminal, closing, treatment, picks. One file. Locks editorial shape.
2scripts/generate_topic_page.py2-3 hoursGeneric version of the crypto sub-hub generator that reads data/topics/<slug>.yaml + dereferences picks against existing bed JSONs. Validates the schema covers what the existing pages need.
3Backfill 1 topic into YAML1 hourPick Bitcoin (the most-developed sub-hub). Re-emit its current state as data/topics/bitcoin.yaml. Run the new generator. Diff against the current Bitcoin sub-hub HTML. Iterate the schema until they match.
